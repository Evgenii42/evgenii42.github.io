Scripts and music: creative choices within verifiable constraints

An appealing model response is not enough to assemble an audio experience. In EmTalk's pipeline, a script passes through a judge and editor, while its music plan is checked for timing, transitions and alignment with speech.

  • AI & automationAI & automation

Active script and music workflow definitions

Script and music planning pipelines include code checks and SCRIPT_REVIEW and MUSIC_PLAN_REVIEW handoffs. A next version using blind comparison of music candidates is saved as an inactive prototype.

Based on inspection of n8n configuration on 10 October 2026. Script Studio V1 and Music Director V1 are active; V2.1 is inactive. Definitions and checks were inspected, not executions or finished audio. Actual human approvals, quality, costs and therapeutic effectiveness were not assessed.

From text to an audio plan

  1. Research package
  2. Three script candidates, a judge and an editor
  3. Code checks the script package
  4. Music plan draft and critique
  5. Code checks timing and constraints
  6. The plan goes to review before music generation

Give the model room to choose

In the script pipeline, a model proposes three candidates. A judge from a different model family assesses the package, and a final editor develops the selected version. This separates generation from evaluation. Code checks that the result includes a script, selection rationale, timeline, display cues and a music brief.

Check what can be expressed as rules

The music plan has its own draft-and-critique cycle. Code then checks full duration coverage, scene overlaps and crossfades. Speech windows are calculated from the script; energy must not rise after the midpoint. The plan also constrains the number of candidates and subsequent paid music generation jobs.

End the stage with a clear handoff

The script pipeline outputs SCRIPT_REVIEW and the music pipeline outputs MUSIC_PLAN_REVIEW. The music director does not generate audio itself. It prepares a package for the next stage, keeping the creative proposal, structure and validation results together. A review status signals a handoff; it does not prove that a person has already approved the material.

Next hypothesis: account for the actual voiceover

The inactive Music Director V2.1 prototype uses a manifest of the actual voice track. Three authors propose candidates, two judges receive anonymised packages in different orders, and code detects disputed scores and can refer them to an additional arbiter. This is a further approach under exploration, without claiming that it has replaced the active version or demonstrated better quality.
